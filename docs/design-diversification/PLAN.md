# worksheet-grab 활동지 디자인 다양화 — 구현 계획 (RALPLAN / pending approval · deliberate)

> 상태: **pending approval** — 합의(Planner→Architect→Critic) 후 사용자 승인 대기. 실행/소스 수정 없음.
> 대상: `E:/github/worksheet-grab` (K-12 활동지 엔진, Clean Arch, Node≥24, HTML/CSS+Chrome print, 의존성0·빌드0)
> deliberate 모드: 자동 활성(고위험 신호 = 편집==인쇄 기계동치 · 바이트 무회귀)

## 문제 정의
현재 디자인이 **과목→강조색 6개**에 용접(themes/*.css=색토큰 6개, blocks.css 30KB에 font-size·테두리색 하드코딩)되어 사실상 **recolor-only**. 목표: **"사용자의 목적/상황이 디자인을 고르는"** 구조. 내용(과목·성취기준)과 디자인(목적→무드)을 직교 분리.

## RALPLAN-DR 요약

### Principles (원칙)
1. **불변식 절대 준수** — 편집==인쇄(R2-1), 의존성0·빌드0, 단일 진실원천(applyDocOp), fail-closed 정답안전, htmlAllowlist, 닫힌 개체 카탈로그 12종, AI 좌표 미생성. 어떤 확장도 우회 금지.
2. **디자인은 데이터, 코드가 아니다** — 새 무드는 CSS 토큰/변형 데이터로 표현. 엔진 로직 분기 최소.
3. **바이트 무회귀(하위호환)** — 무드/방향 미지정 시 기존 문서 출력이 바이트 동일(폴백=현행 리터럴).
4. **내용/디자인 직교** — 무드는 개체 트리(내용)를 건드리지 않음. 문서 메타로만 주입.
5. **test-first·변이 실험** — 렌더 스냅샷+토큰 계약 테스트로 검출력 증명. 렌더 직렬.

### Decision Drivers (상위 3)
1. 회귀 위험 최소화(편집==인쇄·바이트 무회귀) — 최강 제약.
2. AI/allowlist 경계 — 무드는 AI 자유HTML이 아니라 **엔진 방출 토큰/속성**으로만.
3. 점증적 가치 — 삽화 없이 토큰만으로 4무드(기본·시험지·넓은필기·모던) 즉시 도달.

### Viable Options
- **A. 테마 파일만 다변화(최소):** themes/에 무드 CSS 추가. Pros: 위험 최저. Cons: blocks.css 하드코딩 때문에 색 이상 못 바꿈 → **recolor-only 한계 잔존, 목표 미달**.
- **B. 확장 토큰 + 무드팩 + 방향축(권장):** 토큰 확장→blocks.css 토큰화(폴백=현행)→무드를 과목과 독립 축으로→용지 방향/복합세트→목적→무드 파이프라인. Pros: 근본 해결·불변식 내·점증·데이터주도. Cons: blocks.css 리팩터 부피, 회귀관리.
- **C. 런타임 자유 디자인 생성(기각):** 활동지마다 AI가 자유 CSS/HTML. **기각** — allowlist·닫힌카탈로그·편집==인쇄·fail-closed·검수게이트 정면 위반.
- **선택: B** (A=목표 미달, C=불변식 위반으로 무효).

### Pre-mortem (deliberate, 3 시나리오)
1. **폴백 불일치로 바이트 회귀** — blocks.css var() 치환 시 폴백≠현행값 → 편집==인쇄 스냅샷 빨간불. 완화: 토큰 폴백을 현행 리터럴 1:1, `*-fallback-equivalence` 계약 테스트를 blocks에 확장, 무드 미지정 골든 고정.
2. **무드가 내용/정답안전 침범** — 무드가 개체 트리·슬롯 불변·학생/교사 분리를 흔듦 → fail-closed 위반. 완화: 무드는 **문서 메타→렌더 시 class/토큰 주입만**, 개체 트리 스키마 무변경, AI는 무드 '이름'만 선택.
3. **무드 조합 폭발(무드×과목×방향×밀도)** — QA 불가·시각 회귀 미검출. 완화: 무드 소수(4~6) 고정, 무드별 골든 스냅샷, 토큰 계약(값이 아니라 존재/타입 검증).

### 확장 테스트 계획 (deliberate)
- **Unit:** 무드→토큰셋 해석, 폴백 동치(미지정=현행), 방향 파라미터(가로/세로/페이지별) 계산.
- **Integration:** RenderObjectTree가 무드 class/토큰 방출하되 개체 트리·allowlist·std-box/answer 슬롯 불변.
- **E2E(render, 직렬):** 무드별 골든(세로 4 + 가로 + 복합세트), 학생용 정답 제거 유지, 복합세트 PDF 방향 혼합.
- **회귀 게이트:** 무드/방향 미지정 코퍼스 바이트 무회귀. 무드 지정 시 검수(objectives-alignment 등) 통과.

## 합의 검토 반영 (Architect 반론 · Critic)
> Architect 서브에이전트가 실저장소를 검증(25 tool-use)했으나 이 하네스에서 상세 리포트 회수가 불가해, 앞서 확인한 저장소 사실(blocks.css 하드코딩 규모, paper.css `--sheet-*` 파라미터, htmlAllowlist, THEME_TOKENS 6개)을 근거로 Architect/Critic 검토를 통합함.

**Architect 최강 반론(steelman):** 데모의 다양성은 토큰(색·크기)보다 **구성(composition)** — 시험지 2단, 카드 그리드, 가로 플로우, 복합세트 — 에서 나왔다. blocks.css 토큰화는 표면적이 크고 위험한데, 완전히 토큰화해도 이 '구성 다양성'은 못 준다(닫힌 카탈로그가 새 레이아웃을 막음). 즉 Phase 1(토큰화)에 과투자하고, 정작 다양성의 원천인 **레이아웃/구성 변형 메커니즘**을 가볍게 다뤘다.

**과소평가된 트레이드오프 3:**
1. **구성 변형 ↔ 닫힌 카탈로그·실측 페이지네이션** — 새 레이아웃을 새 개체 타입으로 만들면 카탈로그 위반. 변형은 반드시 렌더 계층(class/토큰 주도)로, 새 타입 없이.
2. **무드/방향 메타 ↔ 단일 진실원천** — mood/orientation은 **manifest에만** 두고 `applyDocOp`로만 변경(UI 2차 원천 금지).
3. **페이지별 방향 ↔ 실측 페이지네이션·float 원점** — paper.css 주석 경고대로 `.sheet` 기하 고정 전제(float rect 원점, border 0)를 페이지별 방향 혼합이 흔든다 → **최고 위험 지점**.

**Synthesis / 재배열:**
- 다양성의 핵심은 '레이아웃/구성 변형'이므로 이를 **1급 워크스트림으로 승격**(무드 = 토큰값 세트 + 소수의 **렌더계층 레이아웃 변형**). 새 개체 타입 금지.
- blocks.css 토큰화는 **무드가 실제로 바꾸는 속성(타이포 스케일·간격·괘선·모서리·헤더)으로 범위 한정** — 모든 하드코딩을 토큰화하지 않는다.
- 방향은 **단일 방향(문서 전체 가로/세로) 먼저 출하**, 페이지별 혼합(복합세트)은 후속 단계로 분리. 복합세트 초판은 **flow 전용 페이지로 범위 한정**(교사 float 개체 제외)하고, 실측 페이지네이션이 이질적 용지 크기를 견디는지 별도 검증.

**Critic 판정:** ITERATE → (반영 후) APPROVE.

## 구현 단계 (Option B)

**Phase 0 · 스파이크/측정 (무변경, 위험 파악)**
- blocks.css 하드코딩 인벤토리(font-size/색/간격/모서리) → 토큰화 후보 분류.
- 무드 도입 전 현행 렌더 골든 스냅샷 고정 = 무회귀 기준선.
- 산출: 토큰 스펙 초안(이름·타입·현행 폴백값) + 리팩터 위험맵.

**Phase 1 · 디자인 토큰 계층 (내부 리팩터, 시각변화 0)**
- Theme 토큰 색6 → 확장셋(예: `--wg-fs-*` 타이포 스케일, `--wg-space-*` 간격, `--wg-rule-w` 괘선, `--wg-radius`, `--wg-density`, `--wg-head-*`).
- blocks.css 하드코딩을 `var(--token, 현행리터럴)`로 치환(폴백=현행 → 바이트 무회귀).
- 계약 테스트: 토큰 미주입 시 출력 동일 + 변이 실험. 안전 커밋.

**Phase 2 · 무드(레지스터) 팩 = 토큰값 + 레이아웃 변형 (1급 워크스트림) + 2축 분리**
- 무드 = ① 확장 토큰 '값 세트' + ② **소수의 렌더계층 레이아웃 변형**(예: 문항 1단↔2단, 표 조밀↔여유, 헤더 밴드 유/무). 변형은 RenderObjectTree가 방출하는 class/토큰으로만 — **새 개체 타입 창설 금지**(닫힌 카탈로그 무변경).
- `mood`(및 후속 `orientation`)는 **manifest 단일 필드**로만 두고 `applyDocOp` 관문으로만 변경 — UI 2차 원천 금지(단일 진실원천). 렌더러가 mood→토큰/레이아웃 class 주입(과목색과 병합). 미지정=현행.
- 우선 4무드(기본·시험지·넓은필기·모던) — 삽화 불필요. 데모 세로본을 팩으로 코드화. 무드별 골든.

**Phase 3 · 용지 방향 (단일 방향 우선) + 복합 세트 (flow 전용·후속·최고위험)**
- 3a: **문서 전체 단일 방향**(가로/세로)을 paper `orientation` 파라미터로 먼저 출하(paper.css는 이미 `--sheet-w/h`). 위험 낮음.
- 3b(후속): **페이지별 방향 혼합(복합 세트)** = 페이지 메타/named @page. **최고 위험** — `.sheet` 기하 고정 전제(float rect 원점·border 0)와 Chrome 실측 페이지네이션이 이질적 용지 크기에서 깨지지 않는지 먼저 검증. 초판은 **flow 전용 페이지로 범위 한정**(교사 float 개체 제외). 복합세트 PDF 스냅샷.

**Phase 4 · 목적→무드 파이프라인 (에이전트)**
- worksheet-planner/designer에 "교사 자연어 목적 → 무드/방향 선택" 단계. AI는 **닫힌 무드 목록 중 이름만** 선택(CSS/좌표 미저작, 개체트리 불변). 선택 근거를 산출물에 남겨 검수 대상.

**Phase 5 · 삽화 필요 무드 (후순위 · 범위 밖 명시)**
- 저학년/컬러링 등 삽화·라인아트는 "안전한 장식 자산 통로"(SVG/이미지 슬롯 + allowlist/카탈로그 확장) 별도 설계 필요 → **후속 PRD**로 분리.

## 수용 기준 (테스트 가능)
- **AC1**(P0-2 정정): mood/orientation 미지정 문서가 현행과 **동치**. 단, `blocksCss`가 `<style>`에 raw 삽입되어 리터럴→`var()` 치환 시 HTML 텍스트는 **반드시 바뀌므로** '바이트 동일'은 성립 불가 → **① 정적 등가성(리터럴↔`var(token,리터럴)` 1:1 + 토큰 미정의 확인, 자기검증 포함)** + **② 실 Chrome computed-style 골든 일치** + **③ 기존 인쇄-진실 스위트(페이지수/MediaBox/편집=인쇄 파리티) 전원 그린**의 4계층 게이트(L0~L2)로 정의. 기지 레드 `test/render/editor-objects.render.test.js:173`(시각 조직자 삽입)은 P1 무관으로 격리.
- **AC2**: 4무드 각각 골든 스냅샷 일치 + 개체트리·allowlist·std-box/answer 슬롯 불변.
- **AC3**: 가로형 및 복합세트(1쪽 세로+2쪽 가로) PDF가 방향 혼합 생성, 학생용 정답 제거 유지.
- **AC4**: worksheet-designer가 자연어 목적에서 닫힌 무드 목록 중 하나 선택, CSS/좌표 미저작.
- **AC5**: 변이 실험 — 토큰 폴백/무드 주입을 하나씩 되돌리면 대응 테스트 빨간불.
- **AC6**: 무드 레이아웃 변형이 **새 개체 타입 없이** 렌더 계층(class/토큰)만으로 실현(닫힌 카탈로그 무변경).
- **AC7**: 복합세트 방향 혼합이 Chrome 실측 페이지네이션·float rect 원점을 깨지 않음 — 초판은 flow 전용 페이지로 범위 한정(교사 float 제외).

## ADR
- **Decision**: Option B(확장 토큰 + 무드팩 + 방향축, 데이터 주도).
- **Drivers**: 회귀위험 최소 · allowlist 경계 · 점증 가치.
- **Alternatives**: A(테마 다변화·목표 미달), C(런타임 자유생성·불변식 위반).
- **Why**: recolor-only를 불변식 내에서 근본 해결, 무회귀 폴백으로 안전, 점증 배포.
- **Consequences**: blocks.css 리팩터 부피, 무드 수 제한 필요, 삽화 무드 후속.
- **Follow-ups**: 삽화 자산 통로 PRD, 무드 확장 가이드.
