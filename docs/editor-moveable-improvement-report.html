결론: 편집기를 다른 오픈소스로 교체할 근거는 없습니다. 현재 manifest → reflow → HTML/PDF 구조를 유지하고, float 개체 조작 UX에 한해 Moveable과 Selecto를 제한적으로 결합하는 것이 가장 낮은 위험의 개선 경로입니다.

3. 확인된 결손과 개선 방안

우선순위 1. 스냅 및 스마트 가이드

확인된 결손 격자는 editor.js에서 배경 이미지로만 표시된다. snap, guideline, snapGrid 구현은 없다. 현재 드래그와 넛지는 좌표를 그대로 rect.xMm/yMm에 기록한다.

Moveable 활용: snappable, verticalGuidelines, horizontalGuidelines, elementGuidelines를 활용한다. 현재 쪽의 인쇄 여백선, 5mm 격자, 같은 쪽 float 개체의 변·중심선을 가이드로 제공한다.

저장 규칙: Moveable 예제의 target.style.transform = transform을 저장 경로로 사용하지 않는다. 결과 좌표와 크기를 mm 단위 rect로 변환해 기존 문서 모델에 커밋한다.

우선순위 2. 마퀴(드래그 박스) 다중선택

확인된 결손 다중선택 상태는 있지만, 빈 캔버스에서 드래그해 여러 개체를 고르는 marquee/lasso 구현은 없다.

Selecto 활용: 현재 페이지의 .wg-float[data-oid]를 selectableTargets로 등록하고, Selecto 결과를 기존 selectedIds로 치환한다. Shift는 기존 additive 선택과 같은 의미로 유지한다.

중요: 이 기능은 Moveable 단독 기능이 아니다. Selecto는 드래그 영역에서 DOM 요소를 고르는 전용 컴포넌트다.

우선순위 3. 여러 float의 임시 일괄 이동·리사이즈

확인된 결손 현재 리사이즈 핸들은 selectedIds.size === 1일 때만 붙는다. 다중선택 뒤에는 정렬·분배만 가능하다.

Moveable 활용: 선택된 float DOM 배열을 target으로 전달하고 groupable 이벤트를 사용한다. 각 개체의 변경 좌표를 하나의 문서 연산·하나의 history 항목으로 커밋한다.

범위 제한: 이는 저장되는 “그룹 개체”가 아니라 일회성 다중 조작이다. 영구 그룹은 별도 스키마 기능으로 분리한다.

우선순위 4. 용지 경계 정책과 배치 안전성

확인된 결손 현재 드래그·넛지는 xMm/yMm를 최소·최대 범위로 제한하지 않는다. 리사이즈는 최소 10mm만 보장한다.

Moveable 활용: bounds로 쪽의 안전 영역을 제한할 수 있다. 다만 현 구현에는 다른 쪽으로 끌면 float를 새 페이지로 옮기는 동작이 있으므로, 즉시 경계를 고정하면 기존 동작을 퇴행시킬 수 있다.

선행 결정: “인쇄 영역 밖 배치 금지”와 “다른 쪽으로 끌면 페이지 이동” 중 우선 정책을 확정한 뒤 구현한다.

회전·영구 그룹·잠금: 지금은 도입 보류

즉시 도입 금지 스키마는 rect{xMm,yMm,wMm,hMm}만 허용하고, additionalProperties: false다. rotation, groupId, locked 필드는 현재 스키마·소스·테스트에 없다. 렌더러도 float에 left/top/width/height만 출력한다.

Moveable의 rotatable을 켜기만 하면 편집 화면의 CSS transform만 바뀌고 저장·재로드·PDF 출력에서 보존되지 않는다. 이 기능들은 새 저장 필드, 렌더 규칙, 도형/텍스트의 회전 기준, 검증, 출력 회귀 테스트를 함께 설계할 때만 검토한다.

4. 통합 설계 원칙

  1. iframe 내부에 생성: 대상인 .wg-float가 teacher iframe 안에 있으므로 Moveable·Selecto도 해당 contentDocument 내부에서 생성한다.
  2. 중복 포인터 처리 금지: Moveable을 적용한 float에는 기존 startFloatDrag/startFloatResize 경로가 동시에 실행되지 않게 교체 또는 명확히 분기한다.
  3. 모델 우선: 조작 중 DOM을 미리보기로 갱신할 수는 있어도, 종료 시에는 반드시 manifest의 rect를 갱신하고 history·dirty·save 경로를 통과시킨다.
  4. 재렌더 수명 관리: reloadTeacherFrame()이 iframe body를 교체한다. 따라서 교체 전 Moveable·Selecto 인스턴스를 destroy하고, 교체 후 새 DOM에 다시 연결한다.
  5. 의존성 정책 준수: 현재 package.json에는 런타임 의존성이 없다. 패키지 설치가 아니라 버전 고정된 브라우저 번들을 벤더링할 경우에도 MIT 고지와 재현 가능한 버전 정보를 남긴다.

6. 추가 검증이 필요한 항목

현재 렌더 테스트는 150% 확대에서 화면 잘림을 검증하지만, 확대 상태에서 float를 실제로 끌어 저장·재로드하는 좌표 정확도는 검증하지 않는다. Moveable 도입 전후 다음 조합을 자동 검증해야 한다.

  • 줌 75% / 100% / 150%에서 드래그 및 스냅 좌표
  • 한 페이지 내 스냅, 페이지 경계 이동, 여러 개체 다중 이동
  • undo/redo, 저장·재시작·재로드, student/teacher/PDF 출력 위치 일치
