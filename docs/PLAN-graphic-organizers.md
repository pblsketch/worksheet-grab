## 0. 한눈에 (비개발자 요약)

- **목표:** Diffit이 주는 시각 조직자(벤다이어그램·KWL·프레이어 등)를 worksheet-grab에서도 **되도록 전부** 만들 수 있게 한다. 빈 틀이 아니라 **교사 요구(교과·학년·주제)에 맞게 내용이 채워진, 바로 인쇄되는** 형태로.
- **핵심 판단:** 표처럼 생긴 조직자(대다수)는 **새 부품 타입을 만들 필요 없이 지금 있는 `표(table)` 기능으로** 만든다. 벤다이어그램 같은 그림형만 SVG(그림)로 따로. **핵심 안전장치(인쇄=편집, 정답 안 새기)는 그대로 지킨다.**
- **왜 안전한가:** 조직자의 '틀'은 프로그램이 정확히 그리고, 안의 '내용'만 AI/교사가 채운다(기존 방식 그대로, API 키 불필요).
- **제외:** 디지털 게임·BINGO 같은 학급 활동·수학 조작도구 — 인쇄 활동지의 목적과 안 맞아 뺀다.

## 1. 목표(Goal)

교사가 한 번의 요청으로 **자기 수업(교과·학년·주제·의도)에 맞게 내용이 채워진, 인쇄 준비된 시각 조직자**를 생성할 수 있게 한다. 단순 빈 템플릿이 아니다.

**성공의 정의:** `compose 중2과학 광합성 --archetype frayer` → 광합성 주제에 맞는 프레이어 모형(정의·특징·예·비예 칸 + 교사용 예시)이 채워진 스캐폴드 → `pipeline` 렌더 시 학생용/교사용 2벌이 인쇄 안전하게 나오고, 검수 게이트 통과.

---

## 2. 원칙(Principles)

1. **만들기 전에 재사용** — 새 스키마 타입을 만들기 전에 기존 `table`·`shape`와 기존 compose/저작 파이프라인을 먼저 쓴다.
2. **인쇄 안전은 타협 불가** — 모든 조직자는 인쇄 시 잘리지 않아야 하며(한 페이지 적합 or 안전 분할), "편집=인쇄" 기계 동치를 유지한다.
3. **닫힌 카탈로그는 닫힌 채로** — AI는 타입·좌표를 임의 생성하지 않는다. 조직자의 구조는 엔진이 결정적으로 만든다.
4. **비어 있지 말고 채워서** — 모든 조직자는 compose(아키타입 + 저작 브리프 + AI 파일큐)에 연결돼 요구에 맞게 채워져 나온다.
5. **점진 출시** — 표 기반 먼저(저위험) → 그림형(SVG) 다음 → 범위 밖 제외.

## 5. ⚠ 코드 근거로 밝혀진 3대 제약 (v3 핵심 보강 — Critic ITERATE 반영)

실제 저장소를 대조해 확인한, **계획에 반드시 반영해야 할 사실**:

### 5.1 정답 제거는 "개체 단위"다 — 표 셀 단위가 아니다
- 근거: `src/usecases/BuildVariants.js` — 학생용은 `answer:true`인 **개체를 통째로 트리에서 제거**. `table` 개체의 `answer`도 **표 전체** 플래그이고, 셀(`{text,colspan,header}`)엔 answer 필드가 **없다**.
- **함의:** "조직자 표에서 특정 칸만 교사용 정답"은 **단일 표 개체로는 불가**(표 전체가 정답이면 학생용에서 표가 통째로 사라짐 = 오작동).
- **해결(2경로):**
  - **compose/블록 경로:** 셀 HTML 안에 `<span class="answer">모범답안</span>` → HTML 2차 방어(`stripElementsByClass(['answer','plot-ans'])`)가 학생용에서 제거. ✅ 셀 단위 정답 가능.
  - **에디터 개체 경로:** "빈 조직자 표(answer:false, 항상 표시) + 인접한 별도 `.answer` 예시 블록(교사용, 학생용 제거)" 패턴. (기존 `content` 블록의 '교사용 예시 답안(.answer)' 관례와 동일)
- **원칙:** 정답이 필요 없는 조직자(KWL·노트정리·3-2-1·성찰 등 다수)는 **빈 구조만** → 가장 단순.

### 5.2 표는 항상 분할 불가(`splittable: const false`)다
- 근거: `schema` — table `splittable`은 상수 `false`. `renderTable`은 `break-inside:avoid`.
- **함의:** 한 페이지보다 큰 표 조직자는 분할되지 않아 **넘침/잘림 위험**.
- **해결:** 각 조직자를 **대상 학년·용지에서 한 페이지에 맞도록 설계**하거나, 큰 조직자(예: 5문단 에세이 설계)는 **여러 개의 표/블록을 세로로 쌓아** 구성(각 조각은 keep-together, 조각 사이에서 페이지 넘김 허용).

### 5.3 그림형은 좌표를 AI가 만들면 안 된다
- 근거: 원칙3 + `renderShape`(generic shape는 `viewBox 0 0 100 100 preserveAspectRatio="none"`로 **왜곡** — 원이 타원 됨).
- **해결:** 그림형 조직자는 **엔진이 소유한 고정 비율 SVG 뼈대 + 이름 붙은 텍스트 슬롯**으로 만든다. AI는 **슬롯의 텍스트만** 채우고 좌표·도형은 못 만진다. generic `shape`는 벤/개념지도에 안 씀(전용 SVG 블록 사용).

## 6. 핵심 설계 — "이중 제작" 방지 (Architect 긴장점 해소)

조직자를 compose 경로와 에디터 경로에서 **두 번 만드는 함정**을 피한다:

- **단일 서술자(Organizer Descriptor):** 각 표형 조직자를 **데이터 스펙 하나**로 정의(headerRows/headerCol/rows + 셀 역할: `student-blank` / `teacher-answer` / `standard-injected`).
- 이 하나에서 **두 표면을 파생:**
  - **(A) compose/생성 표면** — 서술자 → 블록 HTML(또는 `RenderObjectTree`의 table 렌더 재사용).
  - **(B) 에디터 표면** — 같은 서술자 → `table` 개체 삽입(+ '내 블록' 프리셋 재사용).
- **저작 브리프도 서술자에서 파생** — 각 셀에 "여기에 무엇을 채워라"를 자동 생성.

→ **정의는 한 곳, 표면은 둘.** 유지보수·회귀 지점이 하나.

**에디터 삽입 경로 명시(Critic 지적 반영):** 에디터 좌측 "삽입 카탈로그"에 **'시각 조직자' 섹션**을 추가해 내장 조직자를 클릭 삽입(사용자 프리셋과 별개의 **내장 조직자 갤러리**). 이 UI 배선은 Phase 1 범위에 포함(공짜 아님을 인정).

## 9. 수용 기준(Acceptance Criteria — 테스트 가능)

**전역:**
1. `compose <교과> <주제> --archetype <조직자>` → 조직자 + 저작 브리프 포함 스캐폴드 생성.
2. 저작 후 `pipeline`/`assemble` → 학생용/교사용 2벌 렌더 · `validate` 통과(정답 누출 0, 미기입 슬롯 잔존 0).
3. 렌더 테스트: 조직자 존재 확인 · 페이지 수 안정 · **잘림 없음**(A4 최소폰트).
4. keepTogether 조직자는 `break-inside:avoid` 렌더. 한 페이지 초과 조직자는 §5.2 세로 스택으로 안전 분할.
5. 조직자 내 교사 정답은 학생용에서 **물리 제거**(§5.1) — grep 2차 방어 통과.
6. **P1·P2는 `schema/`를 건드리지 않는다**(git diff 무변경 증명).

**조직자별(각 항목마다):** 해당 조직자가 (1) 대상 교과/학년에서 한 페이지 인쇄 적합, (2) 채워진 예시가 주제와 정합, (3) 정답 유형이면 학생용 제거 확인.

## 12. ADR (Architecture Decision Record)

- **결정:** 2트랙(표형=기존 `table` / 그림형=SVG 블록), 새 개체 타입 없음. 단일 서술자로 compose·에디터 두 표면 파생.
- **동인:** 동결 스키마 보존 · 인쇄 안전 · 무API 저작 파이프라인 재사용.
- **검토한 대안:** ②새 organizer 타입(스키마 마이그레이션 과대) · ③에디터 조합만(생성 경로 없음) — 모두 기각.
- **선택 이유:** 표형은 이미 `table`로 충분(회귀 최소) · 그림형은 검증된 svg-graph 패턴 · 어려운 부분(편집형 그림)만 스파이크로 분리.
- **결과(Consequences):** 표형 조직자는 저위험 다량 확보. 그림형은 에디터에서 당장은 "잠금 삽입"(내부 편집 불가) — 완전 편집은 P3로 미룸. 표 셀 단위 정답 제약(§5.1)·표 분할 불가(§5.2)를 설계로 우회.
- **후속(Follow-ups):** P3 편집형 그림 개체 스파이크 · Diffit 실제 명칭 캡처로 조직자명 정정.
