## 4. 반드시 알고 시작할 함정 (전부 이번 세션에 실제로 당한 것)

1. **`editorStyle.js` 의 CSS 는 JS 템플릿 리터럴 안이다.** 주석에 백틱을 쓰면 리터럴이 끊겨
   **편집기 전체가 부팅 실패**한다(`".pill is not a function`). 파일에 경고 주석을 남겨 뒀다.
2. **프로브가 "모든 높이 0"으로 나오면 문서 문제가 아니라 부팅 실패다.** `consoleErrors` 는
   `"Uncaught"` 만 주므로 **Playwright MCP 로 같은 URL 을 열어 콘솔 전문을 읽어라.**
3. **`edit-ui` 서버는 ES 모듈을 기동 시 한 번만 로드한다.** `src/usecases/*`·`src/adapters/*` 를
   고쳤으면 **서버 재시작**이 필요하다(정적 자산 CSS/HTML·`src/editor/*` 는 요청마다 읽는다).
4. **유휴 30초 자동저장이 프로브 문서를 오염시킨다**(`saveController` 의 `autosaveMs`).
   프로브가 개체를 지운 채 30초를 넘기면 그대로 저장된다 → **프로브용 문서는 실행 전마다 재생성**.
5. **캔버스 iframe 은 둘(교사·학생)이고 하나는 숨어 있다.** 첫 번째를 집으면 숨은 쪽을 재서 모든
   rect 가 0 이 된다. `scratchpad/probe-lib.mjs` 가 **보이는 프레임**을 고르게 해 뒀다.
6. **합성 이벤트는 이 저장소에서 반복적으로 결함을 통과시켰다.** 배선 검증은 반드시
   `test/helpers/cdp.js` 의 실마우스·실키보드로. `rightClick`·`hover` 도 추가해 뒀다.
7. **변이 실험 없이 초록을 믿지 마라.** 이번에 수용 기준이 **두 번** 무의미했다(v1·v2). 그리고
   ⑥의 렌더 테스트는 **변이를 못 잡았다** — 아래 5항 참조.

## 5. 미해결로 넘기는 것 (정직하게)

- **⑥ 회귀 테스트가 성립하지 않는다.** `setMode` 세대 가드를 지워도 렌더 테스트가 초록이다.
  CDP 클릭 간격(160ms)이 학생 프레임 재렌더 창 안에 떨어지지 않아 경합이 재현되지 않는다.
  현재 테스트는 **불변식 스모크**로 표시해 뒀다(회귀 방어 아님).
  → **필요한 것**: 서버 응답을 의도적으로 늦추는 테스트 훅(예: 렌더 라우트가 `?delayMs=` 존중).
    그걸 만든 뒤 회귀 테스트로 승급할 것.
- **실 클립보드 붙여넣기 도구 없음.** 합성 `paste` 는 브라우저 기본 삽입을 일으키지 않아 "고쳤다"를
  증명하지 못한다. 대안은 `execCommand('insertHTML')` 재현 + `defaultPrevented` 단정(계획 v3 참조).
- ~~**대장에 추가해야 할 미보고 2건**~~ ✅ **등재 완료** — 대장 §B-2 의 C16(`runReflow` 가
  `updateAll()`/`refreshLayers()` 미호출 → 레이어 목록이 낡음) · C17(`commitTitle` 이 관문을 우회해
  **D10 과 같은 결함이 제목 커밋 경로에 살아 있다**). 둘 다 계획 3단계에서 닫는다.
- **변이 실험 도구 주의(이번에 당함)**: 이 저장소 소스는 **CRLF** 다. 문자열 `\n` 으로 줄을 지우는
  변이 스크립트는 **조용히 미적용**되고 그대로 초록이 나온다("변이를 못 잡았다"로 오독하기 쉽다).
  줄 단위로 고치고 **적용 줄 수를 스스로 단정**할 것 — `scratchpad/mutate.mjs` 참고.
- **브라우저 모듈 단위 테스트에서 중첩 `data:` URL 은 base64 로**: `encodeURIComponent` 는 작은따옴표를
  인코딩하지 않아 안쪽 URL 을 `from '…'` 에 넣는 순간 문자열이 끊긴다(`review-chip-stale.test.js` 머리말).
- **미선택 float 은 몸통 클릭으로 선택되지 않는다**(래퍼가 `pointer-events:none` — ⠿ 가 유일한 진입점).
  프로브에서 float 선택이 0으로 나오면 결함이 아니라 설계다.

## 5.5 검증 절차 (2026-07-29 개정 — 시간 비용 때문에)

렌더 전량 1회가 **10분 이상**이다(149건 직렬, 건마다 Chrome 기동, PDF 단건은 45초). 단계마다 전량을
돌리면 그것만으로 한 시간이 넘는다. 그래서 이렇게 나눈다.

| 시점 | 명령 |
|---|---|
| 개발 중 | `npm run test:unit` + **편집기 렌더만** — `node --test --test-concurrency=1 test/render/editor-*.render.test.js` (98건) |
| **병합 직전에만** | `npm run test:render` 전량 1회 |

시간의 큰 몫은 PDF·export·파이프라인 스위트이고 편집기 수정과 무관하다. 다만 **병합 전 전량은
생략하지 않는다** — 편집기 변경이 export 경로를 깨뜨린 전례가 있다.

**그 밖에 이번에 대가를 치르고 배운 절차 2가지**
- **재현 시나리오는 계측값부터.** C16 재현에 4회를 태우고 실패했다. `document.body.dataset.reflowRuns`
  /`reflowChanges` 같은 기존 계측을 먼저 읽어 "그 경로가 돌기는 하는가"를 가른 뒤 시나리오를 짠다.
- **변이 스크립트는 줄 단위 + 적용 줄 수 단정.** 소스가 **CRLF** 라 문자열 `\n` 매칭이 조용히 빗나가
  "변이를 못 잡았다"로 오독하기 쉽다. `scratchpad/mutate.mjs` 참고.
- **플레이크 판정은 A/B 숫자로.** 인상으로 "플레이크겠지" 하지 말고, 변경 전/후 각 5회를 돌려
  실패 횟수를 비교한다(`scratchpad/ab-editor-ai.sh` 형태).
- **전량 렌더는 다른 렌더 작업과 겹치지 말 것.** 배경 실행 여러 개가 겹친 뒤 전량에서
  `paginate.render.test.js` 가 **1초 만에 파일 단위로 죽었다**(개별 테스트 ✖ 없이). 단독 재실행은
  11/11 초록(72초). 자원 경합 징후이지 코드 결함이 아니다 — 착수 전 `Get-Process chrome` 개수와
  `wsg-*` 임시 개수를 먼저 확인한다(MEMORY: render-temp-disk-exhaustion).
