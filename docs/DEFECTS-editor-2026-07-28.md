### D8 [P1] '내 블록으로 저장'이 **편집 손잡이를 인쇄물에 굳힌다** (codex+실측)
- 재현: 자유 개체를 선택(리사이즈 손잡이 8개가 붙은 상태) → 우클릭 → 내 블록으로 저장 → `GET /presets`.
  저장된 html 이 **`<div class="wg-float-handle" aria-hidden="true">⠿</div>` 로 시작**하고
  `wg-resize-handle` 도 포함한다. 이 프리셋은 삽입 시 `richtext.html` 이 되므로 **학생 배포본에
  ⠿ 와 파란 사각형이 인쇄된다.**
- 원인: 제거 규칙이 `selection.js` 의 `readField`/`readHtmlField` **안에만** 있었고,
  `saveObjectAsPreset` 은 `el.innerHTML` 을 날것으로 보냈다 — 같은 규칙이 두 벌로 갈라져 있었다.
- 수정: `innerHtmlWithoutChrome()` 를 export 해 **DOM 을 콘텐츠로 굳히는 모든 경로가 하나를 쓰게**
  했다. 곁들여 프리셋 저장이 `res.ok` 를 확인하지 않아 서버가 거절해도 "저장했습니다"가 뜨던 것도
  고쳤다(`fetch` 는 4xx/5xx 에 throw 하지 않는다).

### D9 [P1] 병합된 칸을 다시 병합하면 **표 구조가 무너진다** (codex+단위 재현)
- 재현: 3열 표에서 B+C 를 병합한 뒤 A 를 오른쪽으로 병합한다. 결과 행이 덮는 열 수가 **2**인데
  표의 열 수는 3 — 칸 하나가 사라진 것처럼 보인다. 숨은 칸이 `colspan:2` 를 그대로 들고 있다.
- 원인: `cell.colspan = span + 1` — 흡수 대상이 **이미 여러 칸을 덮고 있어도 항상 +1**만 했고,
  흡수돼 숨은 칸의 span 도 지우지 않았다.
- 수정: 계산을 순수 함수 `mergeCells(rows, {r,c}, dir)` 로 떼어 내고(단위 8건),
  ① 대상의 span 을 **합산**, ② 숨은 칸의 span 제거, ③ 축이 어긋나는 병합(가로로 흡수할 칸이
  세로로 더 걸친 경우)은 **거절**한다 — 조용히 깨진 표를 만드는 것보다 무동작이 낫다.

### D10 [P1] 타이핑 직후의 명령이 **직전에 친 글자까지 함께 되돌린다** (codex+단위 재현)

  명령뿐 아니라 방금 친 글자도 사라진다.
- 원인: 타이핑은 유휴 500ms 로 묶여 확정되는데, `applyDocOp` 이 대기 중인 타이핑을 먼저 확정하지
  않고 문서를 바꾼 뒤 `history.commit()` 을 불러 **타이핑과 명령을 한 상태로** 찍었다.
  원래 이 목적의 `history.run(fn)` 래퍼가 있었지만 **호출부가 하나도 없는 죽은 코드**였다.

### D12 [P1] **모드 토글 경합** — 늦게 끝난 전환이 화면을 되돌린다 (계획 1단계 ⑥)
- 재현: '학생용'을 누른 직후(재렌더가 끝나기 전) '교사용'을 누른다. 버튼은 교사용인데 화면은
  학생용으로 남는다.
- 원인: `setMode` 가 버튼은 동기로 바꾸고 프레임은 `await` 뒤에 바꾼다. 학생 프레임 재렌더는
  저장+서버 조립이라 수 초 걸리는데, 그 사이 시작된 두 번째 호출이 먼저 끝나면 **늦게 끝난 첫
  호출**이 클로저의 낡은 `m` 으로 프레임 가시성과 `body.dataset.mode` 를 되돌린다.
- 수정: 세대 번호(`modeSeq`)를 두고 `await` 뒤 자기 세대가 최신일 때만 화면을 만진다(마지막 의도가
  이긴다). 커밋 `1079e20`.
- ⚠ **회귀 테스트가 성립하지 않았다.** 가드를 지워도 렌더 테스트가 초록이다 — CDP 클릭 간격(160ms)이
  학생 프레임 재렌더 창 안에 떨어지지 않아 경합이 재현되지 않는다. 현재 테스트는 **불변식 스모크**로
  표시돼 있고 가드의 근거는 코드 논증뿐이다. 승급하려면 서버 응답을 늦추는 테스트 훅이 필요하다.

### D13 [P1] 검수 칩의 **낡은 측정이 최신 결과를 덮어쓴다** (계획 1단계 나머지, 단위 재현)
- 재현(단위, 결정적): 폰트가 아직 안 붙은 상태에서 측정이 예약되면 `fonts.ready` 대기에 걸린다.
  그 사이 교사가 float 을 지우고 재렌더가 일어나 올바른 검수(겹침 0건)가 칠해진다. 이후 대기가
  풀리면 **예약 시점의 낡은 모델**로 다시 재서 이미 지운 개체에 대한 경고가 되살아나 최신 결과를
  덮는다. 그 값은 다음 재렌더까지 화면에 남는다.
- 원인 ①: 스테일 가드가 `getTeacherDoc() !== teacherDoc` 로 Document **정체성**을 봤다. 그런데
  `reloadTeacherFrame` 은 흰 깜빡임을 없애려고 iframe 을 갈지 않고 `body.innerHTML` 만 교체하도록
  설계돼 있어(`editor.js:231-245`) teacher 문서의 정체성은 편집기 수명 내내 그대로다 — 그 가드는
  **사실상 한 번도 트립하지 않았다.**
- 원인 ②: 폰트 대기 표식이 **문서당 하나**(`fontsWaitingOn === teacherDoc`)였다. 정체성이 안 갈리므로
  최초 로드에서 한 번 대기하고 나면, 이후 폰트 게이트에 걸린 측정은 **영영 재예약되지 않는다**
  (새 글리프 때문에 `fonts.status` 가 'loading' 으로 되돌아가는 일은 실제로 일어난다) → 검수 결과가
  조용히 낡은 채 굳는다.

### D15 [P1] 표 셀·조각을 편집하는 동안의 붙여넣기가 **정규화를 통째로 건너뛴다** (계획 2단계 ①)
- 재현: 표 셀이나 조각(제목 배지·학습목표 문장·선지 등)을 더블클릭해 편집 중에 Word/HWP/웹에서
  복사한 내용을 붙여넣는다. `paste` 리스너가 조기 반환해 **브라우저 기본 삽입**이 들어간다.
- 원인: 편집 세션 소유자가 셋인데(`selection.state.editingId` · `tableEdit.editingCell` ·
  `partEdit.editingEl`) 리스너가 **selection 것만** 봤다(R1). 셀·조각은 지역 상태만 세우므로
  `state.editingId` 는 null 이다.
- 피해 범위(정확히): 셀·조각은 `textContent` 로 되읽으므로 **모델은 오염되지 않는다**(계획 v2 정정).
  그러나 화면 DOM 에는 `style`·`class`·중첩 `<table>` 이 그대로 남고, **리플로우는 그 DOM 을 재서
  페이지를 배정한다** — 조판이 붙여넣은 쓰레기 마크업의 높이로 결정된다.
- 수정: 판정을 **이벤트 대상**으로 넓혔다(D1 의 단축키 가드와 같은 규약) — 세 소유자를 알 필요
  없이 "이 노드가 지금 편집 중인가"(`closest('[contenteditable="true"]')` + `[data-oid]` 안)만 본다.
  되읽기는 selection 이 소유한 개체일 때만 여기서 하고, 셀·조각은 각 모듈의 기존 `input` 리스너에
  맡긴다(`insertHTML` 은 `input` 을 정확히 1회 발화한다 — 계획 0.5단계 프로브 실측).
- ⚠ **함정(실제로 당함)**: 첫 구현에서 `e.target instanceof Element` 로 판정했더니 **정규화가 전
  경로에서 죽었다**. 이 모듈은 부모 문서 realm 에서 로드되고 캔버스 요소는 **iframe realm** 의
  Element 라 크로스 realm `instanceof` 가 언제나 false 다. 대조군 테스트가 이 회귀를 잡았다.
- 검증: 렌더 신규 4건(`editor-paste-scope.render.test.js`) — 셀·조각 정규화 배선, **모델까지 반영돼
  재렌더 뒤 생존**, 편집 중이 아니면 무개입, 개체 본문 대조군. 변이(가드를 `editingId` 기준으로
  되돌림)로 신규 3건만 빨강·대조군 2건은 초록 유지.
- ⚠ **이 테스트가 증명하지 않는 것**: "수정 전에 오염이 실제로 들어온다". 합성 `paste` 는 브라우저
  기본 삽입을 일으키지 않아 그 오염을 재현할 수 없다(실 클립보드 도구 부재). 대신 **정규화 배선
  유무**(`defaultPrevented`)와 **정규화된 내용의 실제 삽입·모델 반영**을 잰다.

### D14 [P1] `insertHTML` 이 정규화 산출을 **다시 오염시킨다** (미수정 — 계획 2단계에서 발견)
- 재현: richtext 개체 본문(`<p>` 안)에 캐럿을 두고 **여러 줄**(정규화 산출의 `<br>`) 을 붙여넣는다.
  결과: `<p>본문 문단<span style="font-size: 10.5pt;">붙인값</span></p>칸` — 앞부분에 `font-size` 가
  인라인화되고 뒷부분은 `</p>` **밖으로 튀어나온다**(문단 구조 파괴).
- 원인(프로브 `scratchpad/probe22` 로 확정): Chrome 의 `execCommand('insertHTML')` 이 `<p>` 안에
  블록 경계(`<br>`)가 든 조각을 넣을 때 문단을 쪼개면서 삽입 지점의 computed style 을 인라인으로
  보존한다. **`<p>` 밖 삽입·표 셀·조각에서는 일어나지 않는다**(전부 깨끗하게 들어갔다).
  `execCommand('styleWithCSS', false, false)` 는 이 동작을 바꾸지 못한다(반환 true, 결과 동일).
- 왜 중요한가: richtext 는 `innerHTML` 로 되읽으므로 **이 오염은 모델에 저장된다** — 정규화 정책
  ("속성을 하나도 남기지 않는다")이 마지막 한 걸음에서 뚫린다.
- 후보 처방: 삽입 조각을 마커로 감싸 넣고(프로브 실측 — `<p>` 밖에서는 마커가 속성 하나로 온전히
  살아남았다) 삽입 후 마커 안만 정리·unwrap. **`<p>` 안에서도 마커가 살아남는지 재실측이 선행**이다.
  Range API 직접 삽입은 `input` 이 안 나 되읽기·undo 정합이 깨지므로 기각.
- 현재 상태: 렌더 테스트에 `todo` 로 등록해 **실행하되 스위트를 빨갛게 만들지 않는다**(숨기지 않음).

### D16 [P1] 제목 커밋이 문서 변경 관문을 우회한다 — 앱바 미동기화(⑧) + 타이핑 삼킴(C17) (계획 3단계 ⑨)
- 재현 ⑧: 제목을 고쳐 확정한 뒤 Ctrl+Z. **모델은 되돌아가는데 앱바는 새 제목을 그대로 단다.**

  앱바 제목은 아예 어느 경로에서도 모델을 따라가지 않았다(계획 3단계 표의 `docTitle` 열이 전부 ✗).
- 수정: ⓐ `syncDocTitle()`(제목도 문서에서 파생되는 뷰)을 만들어 `applyDocOp`·`onHistoryRestore`
  둘 다에서 부른다 — 편집 중(`contenteditable`)에는 건드리지 않는다. ⓑ `commitTitle` 을

  ⑧ 빨강, E(`commitTitle` 을 관문 우회로 되돌림) → **C17 만** 빨강(메시지가 증상 그대로).

  않는다**(그 형태로는 변이 E 가 초록이었다). 커밋만 `evaluate` **한 번으로 압축**해 창 안에 넣었다
  — `click()`/`blur()` 는 합성 dispatch 가 아니라 브라우저의 진짜 클릭·포커스 경로라 건너뛰는 것은
  좌표 히트테스트뿐이고, 그 배선은 ⑧ 테스트가 실마우스로 덮는다.
  **D12 승급 단서**: 그쪽도 같은 이유로 재현이 안 됐을 수 있다 — 서버 훅을 만들기 전에 이 압축
  기법부터 시도해 볼 것.

### D17 [P1] 타이핑한 내용이 썸네일·검수에 반영되지 않는다 (⑦) + 리플로우가 레이어 목록을 안 고친다 (C16)

- 원인: 파생 뷰 갱신 조합이 경로마다 달랐다(R3). 타이핑 경로(`onSelectionDirty`)는 `updateAll` 만
  부르고 썸네일·검수를 아예 안 불렀다. 리플로우가 대신 불러 주지만 리플로우는 **페이지 배정이
  바뀌었을 때만**(`changed`) 갱신하므로, 페이지가 안 밀리는 편집에서는 아무도 갱신하지 않는다.

  **읽기 전용 계약**(문서를 바꾸지 않고 history 단계도 쌓지 않는다)이라 리플로우·검수와 고리가 생기지 않는다.

- ⚠ **C16 은 고쳤지만 증명하지 못했다.** `runReflow` 도 같은 관문을 쓰게 해 `updateAll`/`refreshLayers`
  누락은 사라졌지만, **회귀 테스트를 세우지 못했다** — 리플로우가 페이지 간 재배정을 일으키는 조건을
  만들지 못했다. 시도: ⓐ 1쪽 문서를 넘치게 채움(쪽 수는 `pages` 배열 그대로라 새 쪽이 안 생긴다)

  `changed:false` 인지 미확인). 해당 테스트는 `skip` + 재시도 지침과 함께 남겼다.
  **다음 세션**: `document.body.dataset.reflowRuns`/`reflowChanges` 계측이 이미 있으니 그 값부터 읽어
  리플로우가 도는지를 가른 뒤 시나리오를 다시 세울 것.

### D18 [테스트 하네스] AI 취소 시드가 **고정 30ms** 만 기다려 부하에서 거짓 실패한다
- 증상: 전량 렌더에서 `editor-ai.render.test.js` 의 `ai-panel-closed-after-cancel` 가 `'false'` —
  "취소해도 패널이 안 닫힌다"로 읽히지만 **제품 결함이 아니다**.
- 원인: `testSeed.js` 가 취소 버튼을 누른 뒤 `await wait(30)` 로 고정 대기하고 패널 존재를 쟀다.
  그런데 `closePanel({cancel:true})`(`ai.js:630-638`)은 취소 POST 를 **서버로 보내고 await 한 뒤에야**
  `state=null; render()` 로 패널을 지운다. 부하가 걸리면 그 왕복이 30ms 를 넘는다.
  같은 목적의 **폴링이 다른 시드에는 이미 있었다**(`ai-apply-cancel-others`) — 이 한 곳만 고정 대기였다.
- 수정: `pollUntil(() => !document.getElementById('ai-panel'), { timeoutMs: 15000 })` 로 관례 통일.
- **판정 근거(중요)**: 3b(파생 뷰 수렴) 회귀인지 가리려고 `editor.js` 만 3b/HEAD 로 바꿔 각 **5회씩**
  돌렸다 — **양쪽 다 0/5 실패**. 즉 3b 와 무관하고, 유휴 단독으로는 재현되지 않는 **부하 의존**이다.
  그래서 **회귀 테스트로 고정하지 못했다**(부하를 결정적으로 만들 수단이 없다). 고정 대기를 폴링으로
  바꾼 것은 원인 제거이지 테스트로 증명한 수정이 아니다.
